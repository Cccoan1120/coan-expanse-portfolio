# 霄汉无垠 COAN EXPANSE 个人网站 PRD

## 0. 现行单页基线（2026-08-17）

本节描述当前已批准的产品范围，并覆盖本文后续仍保留的多页历史方案。历史章节用于追溯，不再作为实现要求。

- 技术栈保持 React 19、Vite、TypeScript 和 React Router。
- 首页信息顺序固定为首屏、项目、生活、关于、联系。
- 顶部导航固定为“项目 / 生活 / 关于 / 联系”，全部指向首页锚点，品牌标识返回顶部。
- 首页直接展示 7 个 Logo 作品、5 个可展开方案与 6 条生活记录。Mine 是唯一跨两列重点项目，其他 6 个 Logo 作品组成桌面双列、移动单列的编号项目墙。
- Logo 项目墙只加载本地 Logo，不加载产品界面截图；方案展示不加载 Logo。17 个项目数据仍保留连续唯一的 1-17 `showcaseRank`，5 个支撑型历史项目不进入首页。
- `#projects`、`#life`、`#about`、`#contact` 和 `#project-<slug>` 为稳定首页锚点。旧 `/projects`、`/life`、`/projects/:slug` 地址替换跳转至对应锚点，无效项目 slug 保持 404。
- 旧项目索引、生活页、Mine 与 Orbito 案例源码及截图资产继续保留，但不进入正常导航和浏览路径。
- 视觉继续使用“霄汉无垠 / COAN EXPANSE”的深空、轨道、冰蓝与琥珀语言，只借鉴参考站的编号、Logo 舞台和信息密度，不复制其素材、文案或个人符号。
- 项目卡、按钮采用 8px 圆角；中文与正文使用 Noto Sans SC，英文项目副标题使用本地 Cormorant Garamond，元数据使用 JetBrains Mono。
- 发布验收必须覆盖内容与隐私扫描、类型检查、单元测试、生产构建、基于最新 `dist` 的 Playwright、320-1920px 无横向溢出、axe 严重级问题和减少动画模式。

## 1. 文档目的

本文档定义“霄汉无垠 COAN EXPANSE”个人网站的产品目标、目标用户、信息架构、功能范围、内容规范、质量门槛和验收标准，作为设计、开发、内容更新与发布验收的共同依据。

本文档以仓库中的现有实现为基线。当前网站已具备首页、项目索引、旗舰案例、个人经历、简历下载和联系入口；PRD 的作用是把这些能力整理为稳定的产品约束，并明确正式发布前后应继续完善的事项。

## 2. 产品概述

### 2.1 产品名称

- 中文品牌：霄汉无垠
- 英文品牌：COAN EXPANSE
- 所有人：陈宵瀚 / Coan Chen

### 2.2 一句话定位

一个面向招聘者、用人经理及产品与 AI 同行的证据型个人作品集，通过可检索的项目档案和完整案例，展示将模糊问题拆解为可运行产品的能力。

### 2.3 核心主张

> 把模糊问题拆成轨迹，把判断落成可以运行的产品。

网站不只回答“做过什么”，还要让访问者快速看清：

1. 面对的真实问题是什么；
2. 个人承担了什么角色；
3. 做出了哪些关键判断与产品决策；
4. 有哪些可公开、可复核的结果和证据；
5. 哪些信息因隐私、保密或项目状态不能公开。

### 2.4 产品背景

传统个人简历受篇幅限制，往往只能列出项目名称、职责和关键词，难以完整呈现跨产品、AI、数据分析和商业研究的复合能力。常见作品集又容易出现三类问题：

- 项目很多，但缺少层级，访问者无法快速判断重点；
- 截图很多，但缺少问题、决策、结果与个人贡献的叙事；
- 视觉表达突出，但内容真实性、隐私边界和可访问性不足。

霄汉无垠需要用清晰的项目分层、证据化案例与稳定的信息架构，降低招聘者的理解成本，同时保持具有辨识度的深空观测站视觉语言。

## 3. 产品目标

### 3.1 用户目标

- 让首次访问者在 10 秒内理解网站所有人的姓名、职业方向与核心能力主张。
- 让招聘者在 60 秒内找到与岗位最相关的项目，并判断个人角色和项目状态。
- 让深度评估者通过旗舰案例理解“问题—决策—证据—结果—边界”的完整闭环。
- 让有进一步沟通意愿的人无需查找其他渠道即可获取简历或发起联系。

### 3.2 产品目标

- 建立一致、可信、易维护的个人专业品牌。
- 用真实项目和可公开证据支撑 AI 产品、数据分析、自动化工具、商业与研究四类能力。
- 兼顾快速浏览与深度阅读，不迫使所有项目都生成内容单薄的独立页面。
- 在桌面端和移动端提供完整、可访问、无明显性能负担的浏览体验。
- 让新增项目、替换截图、更新简历和调整精选顺序具备明确的维护路径。

### 3.3 成功指标

#### 发布验收指标

- 5 名目标用户进行首次浏览测试时，至少 4 人能在 10 秒内说出网站所有人的主要职业方向。
- 5 名目标用户中，至少 4 人能在 60 秒内找到一个与指定岗位能力相关的项目，并说明个人角色。
- 首页、项目索引、Mine 案例、Orbito 案例四条核心路径均可通过键盘完成浏览和关键操作。
- 自动化扫描不存在 critical 或 serious 级无障碍问题。
- 320、375、414、768、1280、1440、1920px 视口下无横向溢出。
- 所有公开链接、图片、简历下载与联系入口可用，不出现死链或占位内容。

#### 发布后观察指标

在不收集敏感数据的前提下，可选择接入隐私友好的匿名统计，观察：

- 首页到项目索引的点击率；
- 首页精选项目的进入率；
- 旗舰案例的阅读完成趋势；
- 简历下载、邮件和微信入口的触发次数；
- 404、资源加载失败和前端异常数量。

若 V1 不接入统计工具，则以上指标通过招聘沟通反馈、链接参数和人工记录评估，不将埋点作为发布阻塞项。

## 4. 非目标

以下能力不属于 V1 范围：

- 用户注册、登录、评论、收藏或社区功能；
- 在线博客 CMS、后台内容管理系统或多人协作发布；
- 为每个项目强制创建独立详情页；
- 直接承载 Mine、Orbito 等项目的业务数据或账号体系；
- 公开客户数据、儿童原始对话、内部指标、模型密钥或服务端凭据；
- 为视觉效果引入强制滚动吸附、滚动视差、无意义 3D 球体或大面积霓虹渐变；
- 未经授权复制其他作品集的视觉资产、布局母题或品牌表达；
- 通过 NASA 标志或措辞暗示官方合作、认可或背书。

## 5. 目标用户

### 5.1 主要用户：招聘者与 HR

**目标**：快速判断候选人的方向、经验范围、代表项目和基本匹配度。  
**特点**：浏览时间短，优先关注清晰定位、项目层级、简历和联系方式。  
**核心需求**：在一到两屏内获取关键信息，并能快速跳转到全部项目。

### 5.2 主要用户：用人经理与面试官

**目标**：评估问题拆解、产品判断、技术理解、数据思维和实际交付能力。  
**特点**：愿意深入阅读，但需要可信证据和明确的个人贡献。  
**核心需求**：查看完整案例、关键决策、成果、边界和项目链接。

### 5.3 次要用户：产品、AI 与数据同行

**目标**：了解项目方法、寻找交流或合作机会。  
**特点**：会关注项目细节、技术栈、公开仓库和方法论。  
**核心需求**：按领域检索项目，并通过 GitHub、邮件或微信继续交流。

### 5.4 内容维护者

**目标**：低成本更新项目、素材、简历和联系信息。  
**特点**：需要在不修改页面结构的情况下完成常规内容维护。  
**核心需求**：集中式内容源、明确的项目层级、图片规格和发布检查清单。

## 6. 核心使用场景

### 场景 A：招聘者首次浏览

1. 从简历、招聘平台或分享链接进入首页；
2. 看到姓名、职业方向和核心主张；
3. 快速浏览 17 个项目中的 3 个代表项目；
4. 通过三段工作方法理解项目之间的能力联系；
5. 在关于区域确认求职方向与背景，进入项目索引、下载简历或发起沟通。

### 场景 B：面试官核验旗舰项目

1. 从首页或项目索引进入 Mine / Orbito；
2. 查看项目背景、角色、状态与公开边界；
3. 按顺序阅读问题、关键决策、界面证据和产出；
4. 打开在线体验或 GitHub；
5. 在面试中围绕具体证据继续提问。

### 场景 C：按岗位能力筛选

1. 进入全部项目；
2. 按 AI 产品、数据分析、自动化工具、商业与研究筛选；
3. 使用关键词搜索标题、简介、角色或技能；
4. 展开非旗舰项目摘要，或进入旗舰案例；
5. 分享保留当前筛选条件的 URL。

### 场景 D：移动端快速查看

1. 从聊天软件打开分享链接；
2. 在窄屏下阅读首屏与精选项目；
3. 打开移动导航，在首页、项目库和关于之间跳转；
4. 查看项目截图、下载简历或打开联系方式；
5. 全程不发生横向溢出、不可关闭弹窗或依赖悬停的操作。

## 7. 产品原则

1. **证据优先**：产品截图、调研照片、公开仓库和可核验结果优先于装饰。
2. **重点分层**：旗舰项目讲完整闭环，次级项目承担能力证明，归档项目提供广度。
3. **事实与边界并列**：结果、状态、限定条件和隐私边界必须同时表达。
4. **快速浏览与深度阅读并存**：首页负责形成判断，索引负责查找，案例负责验证。
5. **视觉服务叙事**：深空、轨道和观测站是导航与空间隐喻，不能压过内容。
6. **默认可访问**：键盘、减少动画、焦点可见和语义结构属于基础功能。
7. **维护成本可控**：常规内容更新不应要求新增页面组件或改变路由。

## 8. 信息架构

```text
首页 /
├─ 首屏：姓名、定位、核心主张、主要行动
├─ 精选项目：17 个项目中的 3 个代表项目
├─ 工作方法：3 段方法与对应项目证据
├─ 关于我：招聘摘要、求职方向、硕士与实践背景、正式肖像
├─ 生活切片：探索真实、持续输入、保持行动
└─ 页脚：品牌、项目库、简历、邮箱、微信、GitHub

项目索引 /projects
├─ 关键词搜索
├─ 领域筛选
├─ 当前结果计数与预览
├─ 3 个近期完成项目
├─ 旗舰项目入口
└─ 其余项目摘要展开

旗舰案例 /projects/:slug
├─ 项目概览
├─ 问题
├─ 关键决策
├─ 产品证据
├─ 产出
├─ 产品边界
└─ 下一个旗舰案例

兜底页 *
└─ 404 提示与返回项目索引
```

### 8.1 当前内容层级

| 层级 | 数量 | 展示方式 | 当前内容 |
|---|---:|---|---|
| 旗舰项目 | 2 | 首页精选、项目索引、完整案例页 | Mine、Orbito |
| 次级项目 | 6 | 首页精选、近期完成或项目索引摘要 | Offer Atlas、Music Market Radar、Tenni Signal 等 6 个项目 |
| 归档项目 | 9 | 项目索引摘要 | OfferExpert、Spider Frame 等 9 个项目 |
| 首页精选 | 3 | 代表项目陈列 | Offer Atlas、Mine、Orbito |
| 近期完成 | 3 | 项目索引重点陈列 | Offer Atlas、Music Market Radar、Tenni Signal |

## 9. 功能需求

优先级定义：

- P0：正式发布不可缺少；
- P1：明显提升求职转化或维护效率，建议首轮迭代完成；
- P2：验证有价值后再建设。

### FR-01 全局导航与页面框架（P0）

**需求说明**

- 所有页面显示统一品牌字标、三项顶部导航、页脚和跳到主要内容的快捷入口。
- 顶部导航固定为“首页 / 项目库 / 关于”；“关于”指向 `/#about`，不把工作方法和联系重复设置为顶级入口。
- `/#equipment` 继续指向工作方法，`/#contact` 继续指向页脚，保证旧链接可直接访问。
- 当前页面或目标应有明确状态。
- 导航打开后焦点进入菜单；按 Escape 关闭后焦点返回触发按钮。
- 页面切换后更新标题、canonical URL 和 Open Graph URL。

**验收标准**

- 鼠标、键盘和触摸均可完成打开、导航和关闭操作。
- 导航关闭时内部链接不可被键盘聚焦。
- 直接访问或刷新核心路由不会返回 404。
- 直接访问 `/#about`、`/#equipment` 与 `/#contact` 均能到达对应内容。

### FR-02 首页首屏（P0）

**需求说明**

- 首屏必须展示姓名、职业方向、核心主张和至少一个主要行动入口。
- 主要行动指向项目内容；次要行动可指向简历或联系。
- 深空星空与克制的观测交互用于建立品牌辨识度，但不能遮挡正文。
- 背景不依赖远程图片或第三方视觉资源。

**验收标准**

- 首屏在 320px 及以上宽度无需横向滚动即可阅读和操作。
- 图片加载失败时仍可通过文字理解页面定位并访问主要入口。
- 开启减少动画后，持续动画停止，内容默认可见。

### FR-03 工作方法与个人表达（P0）

**需求说明**

- 以“找到真正的问题 / 做成可运行的产品 / 用数据与商业约束验证”三段工作方法替代四格抽象能力卡。
- 每段方法必须连接到已存在的项目证据，项目名称与事实从项目数据源解析，不复制维护。
- 关于区域展示招聘摘要、求职方向、硕士与实践背景、正式肖像和简历、邮件、微信入口。
- 生活切片展示“探索真实 / 持续输入 / 保持行动”，总述为“保持好奇，也愿意走进真实现场。”。

**验收标准**

- 首页恰好显示 3 段工作方法，每段包含可理解的描述与至少两个项目证据入口。
- 关于区域的职业与教育事实与公开简历一致，不出现占位符、内部备注或无法核验的夸张表述。
- 生活照片使用描述性替代文本，不公开具体地点、拍摄时间或其他隐私信息。

### FR-04 首页精选项目（P0）

**需求说明**

- 首页固定展示 3 个代表项目，选择结果只在首页内容配置中维护一处。
- 标题明确说明“17 个项目中的 3 个代表项目”，项目总数与精选数量均从数据计算，并提供“查看全部 17 个项目”入口。
- 每个项目展示项目名、定位、个人角色、能力标签、状态或隐私边界以及证据图片。
- 旗舰项目使用“阅读完整案例”进入案例页；非旗舰项目使用“查看项目摘要”进入项目索引中的对应条目。
- 桌面端使用有主次的代表项目陈列；移动端使用自然单列阅读。

**验收标准**

- 精选项目顺序与内容源一致，不在组件中重复维护。
- 跳转后目标项目处于可见区域，并有可感知的当前状态。
- 不依赖悬停才能看到项目名称、角色或操作入口。

### FR-05 全部项目索引（P0）

**需求说明**

- 展示全部项目，支持关键词搜索和领域筛选。
- 四个领域为：AI 产品、数据分析、自动化工具、商业与研究。
- 搜索范围包含标题、英文标题、定位、简介、角色与技能。
- 搜索词写入 `?q=`，领域写入 `?category=`，刷新和分享后保留状态。
- 结果区域展示匹配数量；无结果时提供清空筛选操作。
- 旗舰项目提供完整案例入口；非旗舰项目原位展开摘要。

**验收标准**

- 搜索与筛选可组合使用，非法领域参数不会导致页面错误。
- 清空后恢复全部项目并移除 URL 参数。
- 键盘可以展开和收起非旗舰项目。
- 结果变化通过辅助技术可感知。

### FR-06 旗舰案例（P0）

**需求说明**

- 只有 `flagship` 项目生成完整案例页。
- 每个案例至少包含：项目概览、问题、个人角色、关键决策、产品证据、产出、边界、外部链接。
- 多张截图按叙事顺序展示，并使用描述性替代文本。
- 页面末尾提供全部项目和下一个旗舰案例入口。

**验收标准**

- Mine 与 Orbito 可直接访问、刷新和相互跳转。
- 非旗舰或不存在的 slug 不生成虚假案例，显示明确兜底内容。
- 案例中的结果不使用无法核验的数据；方案测算必须标记限定语。
- 内部或敏感项目的证据使用脱敏或合成演示内容，并明确标识边界。

### FR-07 简历与联系（P0）

**需求说明**

- 提供固定路径的 PDF 简历下载。
- 提供邮件、GitHub 和微信联系入口。
- 微信入口使用可关闭的对话框展示二维码。
- 对话框打开后管理焦点，支持 Escape 关闭并恢复焦点。

**验收标准**

- 简历、邮件、GitHub 链接和二维码资源均可访问。
- 二维码有替代文本，弹窗具有语义化标题和关闭按钮。
- 页面正文不展示手机号、生日或详细住址。

### FR-08 分享与搜索可发现性（P0）

**需求说明**

- 网站语言声明为简体中文。
- 首页包含准确的 title、description、Open Graph 和 Person 结构化数据。
- 核心页面生成正确的 canonical URL。
- 使用独立 favicon 和 Open Graph 分享图。

**验收标准**

- 正式部署后 canonical 和 `og:url` 使用正式域名，不回退到本地地址。
- 分享图为公开可访问的绝对地址。
- 页面标题可区分首页、项目索引、旗舰案例和 404。

### FR-09 内容维护（P0）

**需求说明**

- 项目内容集中维护在单一数据源中；个人信息、工作方法、兴趣和个人媒体映射集中维护。
- 项目必须具有唯一 slug、层级、状态、至少一个领域、角色、简介和隐私状态。
- 图片采用 AVIF / WebP 响应式版本，并提供小尺寸资源和替代文本。
- 替换简历、二维码和分享图时保持固定公开路径。

**验收标准**

- 新增普通项目不需要修改页面组件。
- 重复 slug、重复精选排名、无领域项目、缺失资源或隐私敏感模式会被内容检查阻止。
- 工作方法通过项目 slug 解析证据，项目名称与链接不得在页面组件中另建副本。
- 生活图片缺少完整与 `-sm` 两档 AVIF / WebP、包含嵌入元数据或出现原始 JPG 时，内容检查必须失败。

### FR-10 404 与异常兜底（P0）

**需求说明**

- 未知页面显示品牌一致的 404 页面。
- 未知项目或不开放完整案例的项目显示明确说明，并提供返回全部项目入口。
- 关键图片缺失不应导致整页白屏或导航失效。

**验收标准**

- 任意未知路由均可返回首页或项目索引。
- 控制台不出现导致页面无法交互的未捕获异常。

### FR-11 匿名访问分析（P2）

**需求说明**

- 如需分析访问行为，优先选择不使用跨站追踪、无需采集个人身份的方案。
- 只记录页面、来源类别和关键 CTA 事件，不采集表单内容、二维码图像或敏感查询。
- 上线前明确数据保留周期和隐私说明。

**验收标准**

- 分析脚本不阻塞首屏，不影响无脚本时的核心内容访问。
- 未经明确决策，不在 V1 默认接入第三方营销追踪。

## 10. 内容模型

### 10.1 项目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| slug | 是 | 唯一路由标识 |
| title / englishTitle | 是 | 中英文项目名称 |
| timeframe | 是 | 项目时间范围 |
| tier | 是 | `flagship`、`satellite` 或 `archive` |
| status | 是 | `live`、`maintaining`、`private` 或 `research` |
| domains | 是 | 至少一个能力领域 |
| logo | 是 | 本地 Logo 路径与非空替代文本 |
| showcaseRank | 是 | 单页项目墙唯一连续排序 1-17 |
| featuredRank | 否 | 旧版首页精选排序，保留用于内容兼容 |
| spotlightRank | 否 | 项目索引近期完成项目的唯一排名 1-3 |
| privacy | 是 | 公开或已脱敏 |
| tagline / summary | 是 | 一句话定位与项目摘要 |
| role | 是 | 本人承担的角色 |
| skills | 是 | 与项目相关的能力标签 |
| cover / gallery | 否 | 旧案例页封面与证据图片，不在项目墙加载 |
| links | 否 | 在线体验、GitHub 等公开链接 |
| problem / actions / outcomes / boundaries | 旗舰必填 | 完整案例叙事 |
| metrics | 否 | 可核验指标；方案值需有 qualifier |

### 10.2 内容准入规则

- **旗舰项目**：具备完整问题、决策、证据、产出和边界，可独立支撑面试追问。
- **次级项目**：有明确角色与证据，适合首页曝光，但暂不足以形成完整案例。
- **归档项目**：证明能力广度，在索引中保留简洁、真实、可核验的摘要。
- 项目层级根据公开材料成熟度确定，不根据主观重要性随意提升。
- 不虚构转化率、用户数、性能收益或商业结果。

## 11. 视觉与交互要求

### 11.1 视觉定位

- 类型：Atmospheric / 深空观测站。
- 核心隐喻：星系、轨道、观测坐标和项目放映。
- 内容证据：真实产品界面、调研照片与公开项目素材。
- 主色：午夜蓝黑、恒星银白、低饱和冰蓝、恒星琥珀。

### 11.2 设计约束

- 全站颜色、间距和字体使用统一语义 token。
- 不使用渐变文字、紫蓝霓虹背景、统一圆角卡片网格或大面积玻璃拟态。
- 不用无语义粒子雨、完整同心椭圆或无意义 3D 星球替代真实内容。
- 产品截图不添加伪浏览器或伪设备框，只允许克制的边框、编号和事实说明。
- 强调色面积保持克制，主要用于当前状态、坐标和关键行动。
- 所有触控目标不小于 44 × 44px，焦点状态始终可见。

### 11.3 动效约束

- 动效用于表达当前项目、空间层级和交互反馈。
- 页面离开视口、标签页隐藏或用户选择减少动画时，停止持续帧循环。
- 不使用强制 scroll-snap、滚动视差和统一的整页淡入模板。
- 动效关闭后，不影响内容顺序、可见性和操作结果。

## 12. 非功能需求

### NFR-01 性能

- 首屏核心文字不依赖大图加载后才显示。
- 图片使用合适尺寸、现代格式、懒加载和响应式 `sizes`。
- 首屏关键图可提前加载，其余内容按进入视口加载。
- 正式发布环境以移动端中等网络为基准，目标 LCP ≤ 2.5 秒、CLS ≤ 0.1、INP ≤ 200 毫秒；若未达标，应记录测试设备、网络条件和主要瓶颈。

### NFR-02 可访问性

- 以 WCAG 2.2 AA 为目标。
- 语义化标题层级、地标、链接和按钮名称完整。
- 所有功能支持键盘操作，焦点顺序与视觉顺序一致。
- 对话框、导航和可滚动叙事区域具有可感知名称和焦点管理。
- 支持 `prefers-reduced-motion: reduce`。
- 自动化 axe 扫描不得出现 critical 或 serious 问题。

### NFR-03 响应式与兼容性

- 核心支持宽度：320、375、414、768、1280、1440、1920px。
- 支持当前主流桌面和移动浏览器的最近两个稳定版本。
- 移动端不依赖 hover；桌面端 hover 反馈不得承载唯一信息。
- 所有核心页面无横向溢出，长标题、长链接和中英文混排可正常换行。

### NFR-04 隐私与安全

- 仓库与公开页面不得包含模型密钥、数据库连接串、服务端凭据、客户数据或内部账号。
- KOL 与 Teeni 仅使用脱敏或合成演示证据。
- 儿童原始对话、真实达人邮箱、内部配置字段和内部指标不得公开。
- 生活照公开目录只保留移除 EXIF、GPS、IPTC、XMP、ICC 与方向信息的 AVIF / WebP 衍生图，不复制原始 JPG。
- 外部链接使用安全的新窗口属性；公开资源不依赖带凭据的临时链接。
- 每次提交或部署前运行内容与隐私检查。

### NFR-05 版权与素材来源

- 项目与个人照片仅使用本人拥有或已获授权的素材。
- 原始生活照片保留在网站公开目录之外，只将清除元数据后的响应式衍生图用于页面。
- 替换素材时同步更新替代文本、隐私复核记录与响应式版本。
- 不使用 NASA 影像、标志或署名，不暗示官方背书。

### NFR-06 可维护性

- 内容数据、页面组件和样式 token 职责分离。
- 普通项目增删改不需要新增路由或复制页面模板。
- 发布前依次完成类型检查、单元测试、生产构建和端到端测试。
- 端到端测试以生产输出为目标时，必须先重新构建，避免验证过期 `dist`。

## 13. 数据与隐私策略

### 13.1 可公开内容

- 姓名、职业方向、城市级位置、公开邮箱、GitHub；
- 已授权公开的原版 PDF 简历；
- 公开项目仓库、在线体验和脱敏项目说明；
- 本人拥有或已获授权的产品截图、调研照片和展示材料；
- 本人允许公开的肖像与生活照片脱敏衍生图。

### 13.2 禁止公开内容

- 手机号、生日、详细住址；
- 数据库连接串、API Key、Cookie、服务端配置和内部账号；
- 客户、用户或儿童的原始数据与可识别信息；
- 未经授权的内部指标、邮件、对话、合同或配置截图；
- 无法证明来源或使用权的图片和视觉资产。

## 14. SEO 与分享要求

- 首页描述应明确包含姓名与 AI 产品、数据分析、策略运营或商业研究等核心方向。
- 每个旗舰案例拥有独立、准确的页面标题和描述。
- 正式域名配置到 `VITE_SITE_URL`，生成绝对 canonical 和 Open Graph 地址。
- 分享图在微信、招聘平台和常见社交工具中可正常预览。
- 结构化数据中的姓名、职位和公开链接与页面正文一致。
- P1 可增加 `sitemap.xml`、`robots.txt` 和案例级结构化数据。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 视觉氛围压过专业内容 | 招聘者无法快速判断能力 | 保持首屏主张和 CTA 高优先级，真实证据优先于装饰 |
| 项目数量增长导致首页过长 | 核心项目失焦 | 首页精选上限 5 个，其余统一进入项目索引 |
| 非旗舰项目内容过薄 | 形成“项目堆砌”印象 | 只展示摘要，不自动创建独立案例页 |
| 内部项目泄露敏感信息 | 隐私与合规风险 | 合成证据、脱敏文案、内容扫描和人工复核并行 |
| 外部项目状态变化或链接失效 | 信任下降 | 发布前逐项核验，并在内容源中维护明确状态 |
| 大图和 Canvas 影响移动端性能 | 首屏慢、耗电和交互卡顿 | 响应式图片、懒加载、暂停不可见动画、减少动画支持 |
| 自动化测试验证过期构建 | 错误判断发布质量 | E2E 前强制重新运行生产构建 |
| 职业方向过多导致定位模糊 | 首屏理解成本上升 | 通过核心主张统一叙事，以项目筛选承载能力广度 |

## 18. 依赖与约束

- 内容依赖真实且已获授权的项目材料、截图、简历和联系方式。
- 正式 SEO 依赖最终域名及 Vercel 环境变量配置。
- 分享预览依赖 Open Graph 图片可公开访问。
- 深空视觉由本地 shader 与 CSS 回退实现，不依赖远程视觉素材。
- 网站为前端作品集，不依赖业务数据库、用户账户或后端 API 才能完成核心浏览任务。

## 20. 需求变更规则

- 新需求必须说明它服务的目标用户、解决的问题和验收方式。
- 仅提升视觉“炫酷度”但不改善理解、信任或转化的需求，不进入 P0。
- 新增第三方脚本、数据采集或外部服务前，必须先完成隐私与性能评估。
- 项目升级为旗舰前，必须同时具备完整叙事、可公开证据和明确边界。
- 任何内容更新不得降低现有键盘操作、减少动画、响应式和隐私基线。
